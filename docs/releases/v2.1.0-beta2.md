## 本次改动

### 导出：一套按钮就够，不再勾选

以前导出要先进「选择模式」、逐个勾选卡片、再点「导出所选」。**现在点一次，四种模式（含系统预设）全部导出成一个 JSON 文件。**

- 按游戏模式排列，每种模式里系统预设在前、自定义预设按编号排列
- 文件名形如 `conway-life-presets-20261127.json`，继续用 v2 文件格式
- 导出保存的是原始图案，**不改变当前场地、历史、游戏模式或已保存的数据**
- 系统预设也计入导出总数，超限会明确提示，不会生成截断的备份

### 导入：会查重了

以前同一个文件导两次就会得到两份副本。现在会真正比较形状：

- **完全重复**指所属模式、格子布局、每格状态都相同。**名称、编号、坐标的排列顺序、外围空白、整体位置都不影响判断** —— 同一个图案挪个位置再导出，导入时也会认出来
- **旋转或镜像后布局不同的，分别保留**（它们是不同的形状）；跨模式的相同布局也分别保留
- 重复项保留本地已有的，不覆盖
- **系统预设计入去重范围** —— 导入一份备份不会再把已有的系统形状复制一份
- 导入完成后分别提示**新增 / 重复跳过 / 无效跳过 / 自动改名**的数量。全部重复也是正常结果，不新增任何形状

### 同名但形状不同：自动加数字后缀

三个不同图案都叫「好玩」，导入结果是 **「好玩」「好玩1」「好玩2」**。后缀在**全部模式的系统与自定义名称**里找最小可用数字，必要时会截短原名，保证总长不超过 16 个字符。

### 预设操作菜单改到右键

卡片左上角那个「＋」按钮去掉了。**在卡片任意位置点右键**，菜单就在鼠标旁边弹出。

- 不会弹浏览器自己的右键菜单，也不会触发拖拽
- **键盘也能用**：卡片聚焦后按菜单键或 `Shift+F10` 打开，上下方向键、`Home`／`End` 选择，`Esc` 或 `Tab` 关闭
- 点菜单外、滚动预设列表、调整窗口或窗口失焦时自动关闭
- **Rule 110 不提供旋转**（一维形状转 90° 没有意义）
- **场地的右键仍然是擦除** —— 这两处不冲突

## 下载与安装

适用于 Windows 10 / 11 x64，**本次 4 个附件**：

- `Conway-Life-2.1.0-beta2-Tauri-Windows-x64-portable.exe` —— **Tauri 免安装单文件**，约 9 MB，双击即用。**依赖系统 WebView2**。
- `Conway-Life-2.1.0-beta2-Windows-x64.exe` —— **Electron 免安装版**，约 96 MB，自带 Chromium 和 Node，**不依赖 WebView2、不依赖任何运行库**。在没有装过 WebView2 的机器（比如学校机房）上用这个。
- `Conway-Life-2.1.0-beta2-Tauri-Windows-x64-setup.exe` —— **Tauri NSIS 安装版**，安装时会自动下载安装缺失的 WebView2。
- `Conway-Life-2.1.0-beta2-SHA256SUMS.txt` —— 上述三个可执行文件的校验值。

**这一版没有 MSI**：WiX 要求版本号里的预发布标识必须是纯数字，`2.1.0-beta2` 会被拒绝，NSIS 没有这个限制。转正式版后 MSI 会恢复。

**在线试玩**：<https://huajitongxue.github.io/conway-life/> 跟的是 `main` 分支，**仍是 v2.0.0，不含 Rule 110 和这轮的形状改动**。要在线试 Beta，用浏览器打开本地的 `web/index.html`（这个目录是自包含的，237 KB，拷到 U 盘就能跑）。

## 验证范围

**自动化层面**：源码语法检查（`node --check` 八个脚本）、`git diff --check`、六处版本号一致性核对、依赖锁文件同步校验、四个附件非空与大小核对、解包后内层程序为 x64 架构核对，以及三个可执行文件的 SHA-256 计算与重新读取复核。

逻辑层有**十三套本地检查脚本、共 255 组**全部通过。这轮新增 `preset_backup_check`（**29 组**，覆盖导出范围、查重键、同名改号、失败回滚），原有的 `preset_io_check` 因删掉勾选式导出从 47 组降到 43 组，其余十一套保持通过。

**没有做的**：没有自动化冒烟测试，没有执行安装测试，产物没有在 CI 之外运行验证过。

**人工验证**：查重规则是否符合直觉、右键菜单开合是否顺手、以及"卡片右键菜单开着时点场地"会不会误擦一格 —— 这三处都要实际跑一遍才知道。

## 已知限制

- **逻辑网格仍是 120×80**，Rule 110 一屏只能看 80 代。
- **形状编辑器在 Rule 110 下没有实际用途**（能打开，但二维图形放到一维场地上会被压成一行）。
- **导入不会主动清理本地已有的重复记录** —— 只保证不再新增重复项。历史上已经重复的条目需要手动删。
- **兰顿蚂蚁仍未实现**。它对固定网格 + 环绕边界是天然冲突的，需要无限画布和一套单独的稀疏数据层，留到以后的版本。
